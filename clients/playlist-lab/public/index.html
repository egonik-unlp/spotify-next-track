Session generators

Autoregressive journeys from one seed, under one shared retrieval policy.

Seed

Spotify URIs, bare track ids, open.spotify.com URLs or vocab indices — one per line. More seed tracks give the model more context.

Models

Both slots run the same seed and the same policy, so the only difference is the algorithm.

Retrieval policy

Units are pool-local score z, so one value means the same displacement for every model. Temperature 0 is greedy.

How to read a journey

Intent
What the model wanted next, not just what it took: score mass by genre, how committed it is (ent 0 = one narrow pocket, 1 = wandering), whether it is reaching for a single artist (conc), and the top-1/top-2 gap (margin). aim is the predicted latent's nearest genres — the target point itself, which only the next-latent families expose.
Diagnostics
The crown's own facets, computed on the journey you are hearing rather than a held-out split — so H here is comparable to the leaderboard's.
Flags
maxrun and hhi measure journey-internal repetition, which artist_adj cannot see: it only counts the seed's artist, so a generator looping on some other artist scores a perfect 0. Cells turn red when a run reaches 3 or concentration reaches 0.25.

Pick a seed and press Generate. One journey costs about one artifact load (~4 s) regardless of length.
